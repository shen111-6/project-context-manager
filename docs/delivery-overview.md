# 面向 AI 开发协作的证据化上下文恢复

Project Context Manager 保存开发目标、断点、WIP 和下一步，并在接手时重新比较 Git 与磁盘证据。它解决新会话需要重建项目状态、旧“已完成/Passed”声明可能过时的问题。

核心由 TypeScript 构建，独立于 VS Code；CLI 与扩展使用同一引擎。Git HEAD/index/磁盘/未跟踪证据与 SHA256 指纹分开记录，交接采用版本化 JSON/Markdown、不可变快照、陈旧预览及并发发布检查。

AI 集成在证据引擎之外：经用户授权的 Codex 适配器返回结构化候选判断，执行 JSON Schema 与来源校验。候选判断不能直接认证功能完成；交接中的文字不能授予继续开发权限。未保存缓冲区不会自动保存，恢复与核验保持只读。

当前 Windows 实际验证包括自动化回归（2026-10-13：9 文件/38 测试）、真实 VS Code 限定流程、独立新聊天接手及七场景离线演示。交付包自检另外验证解压后 CLI 的缺少记录、交接、只读恢复和漂移；其输出记录准确范围。

这体现 Agent 应用中的状态管理、可追溯证据、模型输出校验和宿主集成能力；不涉及模型训练。当前交付定位为 3.0.0-alpha.2：核心功能和演示验收 PASS，既有 Windows/macOS/Linux CI 通过。本次 6,202 文件规模验收通过，6,207 项只读哈希一致；单次大仓库默认采集约 75 秒，建议选择必要模块。GUI 高级验收、用户研究与 Claude/Gemini 运行支持保留为已知限制，不宣称效率提升或准确率。

推荐演示：先运行包内 verify.mjs，观察恢复为何返回 partial；再安装 VSIX，在合成项目中填写目标、生成交接和查看恢复风险；最后修改合成源文件并再次核验，解释当前事实与历史声明的区别。
