# M4 revised scope: Claude Code and Gemini CLI interfaces only

The user explicitly requested interface design for **both Claude and Gemini**, without login or runtime integration this iteration. `packages/adapters/src/ports.ts` defines the neutral capability, input, provenance, candidate, event and cancellation contract. The two ports are interfaces, not placeholder clients claiming success. Codex remains the only implemented client. GUI does not offer nonexistent Claude/Gemini execution buttons.

Data format is shared with the engine. A snapshot is historical data; a trusted current human action grants analysis authority through the host, never through a serialized file. Candidates may carry implementation observations and uncertainties, but no completed certification or development permission. The engine validates source hashes against actually supplied samples and rechecks the current baseline. Missing projects/dirty files are not transferred by an adapter.

## Claude Code design

Detect installed CLI version and required safe options without auth-file access. Use an isolated temporary working directory and independently logged-in CLI. Planned headless JSON output + `--json-schema`; decode `structured_output`, retain usage only if reported. Discover applicable project CLAUDE.md separately from Codex AGENTS override semantics. Supply these as scoped constraints, not command authority.

Before implementation acceptance, prove tools/MCP/skills/hooks cannot run: `--tools ""`, strict empty MCP config, disabled skills/customization and denied prompting. A permission mode alone is insufficient. Official policy documents state that user-level `disableAllHooks` cannot disable managed hooks. If required isolation cannot be established under managed policy, report unavailable rather than relaxing safety. Do not copy login/session stores.

References: [headless + structured output](https://code.claude.com/docs/en/headless), [CLI options](https://code.claude.com/docs/en/cli-reference), [managed hook restrictions](https://code.claude.com/docs/en/hooks).

## Gemini CLI design

Headless CLI provides JSON `response`, `stats` and optional `error`, or JSONL streaming events. Model response must be decoded and validated against the common candidate schema; transport JSON alone is not schema-constrained semantic output. Retain unavailable token counters as null, never zero. Discover scoped GEMINI.md requirements using its actual inclusion/precedence rules after inspecting the selected CLI version; do not blindly reuse Codex/Claude precedence.

A future implementation must prove denied tool policy, no hooks/MCP/extensions or implicit session reuse, safe temporary working scope and cancellation. Do not assume `--sandbox` equals read-only or that an auto-approval allowlist is a deny-all policy. When the CLI cannot provide sufficient isolation, keep manual copy-based recovery with explicit limitations rather than an unsafe automatic client. Existing Google/provider login remains owned by Gemini CLI.

References: [headless output](https://geminicli.com/docs/cli/headless/), [policy engine](https://geminicli.com/docs/reference/policy-engine/), [context files](https://geminicli.com/docs/cli/gemini-md/).
