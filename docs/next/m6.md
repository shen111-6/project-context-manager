# M6 evaluation tooling and local delivery

The offline evaluation package generates a seed-stable, balanced 216-run schedule: 12 case designs × 3 arms × 2 receivers × 3 repetitions. Six separate calibration slots precede freezing. Defaults name Codex/Claude; selecting Codex/Gemini produces the same-sized design. Neither selection installs or invokes an Agent. Sender assignment in the tool arm is balanced. The 12 design names are not implemented/executed benchmark fixtures.

Freeze requires independently reviewed fixture and truth hashes for each case. The manifest hashes its schedule and bindings. A receiving ledger includes actual outcome, environment/model, report/truth provenance, independent scoring review, separate preparation/recovery timing, nullable token counts and continuation result. Review strings and hashes are audit metadata, not cryptographic reviewer authentication. The experiment operator must retain the reviewed files separately from receiver-visible input and verify them.

Scoring rejects duplicate runs, mismatched frozen truth and missing required measurements/annotations. Failed, timed-out and interrupted attempts remain visible; absent runs are pending, absent measurements null. Tokens are grouped within model. Proportions include sample counts and descriptive Wilson intervals; correlated facts and unpaired totals cannot establish superiority. Summaries never certify release acceptance. The scorer's synthetic unit records are unit-test inputs only, not study results.

```sh
node dist/pcm.cjs evaluation-plan
node dist/pcm.cjs evaluation-plan seed codex gemini-cli
# JSON input: {manifest, bindings}; reviewed files remain outside receiver context
node dist/pcm.cjs evaluation-freeze reviewed-bindings.json
# JSON input: {manifest, records}; current human/operator supplies actual measured runs
node dist/pcm.cjs evaluation-score measured-ledger.json
```

Execution protocol: first calibrate six independent fixtures and scoring rubric, then freeze 12 cases and hidden continuation tests. Prepare repository, human-handoff and tool inputs on matching base files; include sender preparation resources separately. Randomize the generated schedule; run each receiver in fresh context with fixed permissions and environment. A human explicitly authorizes continuation only after the recovery report is saved. Score against pre-established tests + independent review, retaining every failure and timeout. Compare paired case/repetition outcomes within the same receiver/model; report uncertainty before any claim of improvement.

Usability protocol remains pending: 12 target developers, unguided A–D tasks, time-to-find-entry, explicit action count, successful real artifact/recovery completion, understood next step/risk and unauthorized changes. Track first-use and configured-use separately. First GUI feedback target 300ms is not a measurement from extension command integration tests. Native keyboard navigation and screen-reader behavior need observed testing.

This delivery is a local alpha. Original M3 full GUI, M4 bilateral runtime, M5 supported-platform/fault and M6 empirical/UX publication gates remain unpassed. No study participants, cross-Agent runs or benchmark efficacy numbers are invented. Claude/Gemini are deliberately interface-only this iteration. No GitHub push or Marketplace publication is performed.
