# Context Health Check

先读取并应用 [共享状态重建规则](state-reconstruction.md)。使用其范围、证据、基线比较、验证与冲突结论作判断；本文件只定义上下文健康分级。

## 检查范围

以当前阶段和下一步任务为范围，定向核对文档与实现、Handoff 基线与相关变化、进度/TODO 与验收证据、决策记录与实际架构。只有需要补足关键证据且成本合理时执行共享规则允许的必要验证。

检查并区分已发现、未发现、未检查/不确定：

- 文档是否明显落后于相关实现，Handoff 是否存在影响当前任务的失效内容。
- TODO 是否有已满足验收但未标记的任务。
- 是否存在重要架构变化却缺少决策记录；按共享规则区分未记录决定与未经确认的实现偏差。
- 可访问聊天/任务记录是否与实际状态冲突；聊天不可访问时不声称已检查。
- 是否混杂多个阶段、重复且已失效的讨论或互相矛盾的下一步。
- 当前任务、约束、风险和验证缺口是否明确，是否足以继续当前会话。

## 分级

| 等级 | 判定 |
|---|---|
| Good | 已核验范围内，当前任务需要的信息一致且足够，关键结论有证据，下一步明确 |
| Warning | 局部信息过期或存在核验/记录缺口，但仍可明确继续；证据不足以建立可靠等级时用暂定 Warning 并说明原因 |
| Poor | 已发现核心架构、阶段、任务或约束的实质冲突/缺失，按现有上下文推进容易做错 |

不使用百分制、伪精确分数或精确 token 阈值。资料不足不能评为 Good，也不能仅凭缺少核验就断言项目状态很差。明确等级是否暂定及证据覆盖范围。

有未提交修改不等于不健康，旧日期不等于过期；具体判断复用共享规则。测试失败如果被准确记录且下一步明确，也不自动导致 Poor：这里评估上下文质量，不是软件质量。

## 输出与后续

```text
Context Health: Good / Warning / Poor（仅选择一项；必要时注明暂定）
Scope: 本次检查范围与未检查内容
Reasons:
- 发现、影响及证据位置
Recommendation:
- Continue current session
  或 Generate handoff and start a new session
Suggested Follow-up: 最小同步/核实动作及目标文档（如需）
```

上下文足够且缺口局部时建议继续并补足；多个阶段和失效内容妨碍推进时建议先 compress 再开新会话。新会话本身不能解决缺失证据，需要在建议中保留核实动作。

默认报告后停止，不改写项目文件、不自动调用 compress、不自动创建新会话。用户已明确要求检查后同步或交接时再执行对应模式。
