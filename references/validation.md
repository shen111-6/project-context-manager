# Skill 验证与维护

仅用于创建、修改或评估本 Skill。不是第四种用户模式，不在正常项目运行时加载，不自动触发真实项目测试。

## 静态验收

1. 用当前环境 skill-creator 的 scripts/quick_validate.py 校验 Skill 目录；记录实际结果。它只检查格式等基础问题，不证明行为正确。
2. 核对 frontmatter、openai.yaml 元数据及默认提示，保证名称一致、允许隐式调用、无未完成脚手架内容。模板的填写说明是有意保留的资源内容。
3. 检查本地链接全部存在、相对路径正确、每份资源有明确调用入口；三个模式均明确依赖 state-reconstruction.md。
4. 以共享规则为唯一公共定义，逐一核对范围、证据顺序、Git 基线、实现分类、验证分类、冲突与不确定性。模式不得另设标准；模板字段对齐共享规则。
5. 检查 compress 的有限写入、restore/health-check 默认只读、继续任务授权和 AGENTS.md 边界是否一致。
6. 检查项目绑定：不得含真实项目名、用户绝对路径、固定仓库/分支/提交、数据库/框架依赖或秘密。协议字段、通用 Git 命令和抽象示例不算绑定。

## 隔离行为验收（单独执行并报告）

需要实际行为测试时，在允许的临时目录构建最小样例，不使用真实项目、不调用外部服务。记录测试前后源文件内容与 Git 状态以核实副作用。不要将下面的预期写进给执行者的场景材料。

| 场景 | 可观察的通过条件 |
|---|---|
| 自定义中文/英文文档与合并状态页 | 复用原文档，不机械创建整套文件 |
| 聊天声称完成，实际仅占位/未接线 | 不误报完成，定位实现缺口 |
| Handoff 属于另一分支/工作树 | 核查当前范围和差异，不照搬未提交成果 |
| HEAD 相同但已修改当前任务代码 | 识别相关变化，重新判断旧验证是否适用 |
| 只有无关文件变化或日期较旧 | 不无依据宣布整个 Handoff 失效 |
| 代码违背 Accepted ADR | 记录偏差，保留决策与理由 |
| 测试失败、被阻碍或超时 | 如实分类，不声称成功；不越界修代码 |
| 无 Git、无 Handoff 或来源不可访问 | 有限恢复并说明缺口，不编造历史 |
| 多项目候选不明、大型多模块项目 | 不猜项目；确定后仅检查所需模块及依赖 |
| 连续 compress，含长约束和未提交历史 | 无流水账累积，关键约束/风险/证据不因行数删除，重要历史可找回 |
| compress 发现大量文档过期 | 重点维护 Handoff，只有明确小范围同步才改其他文档 |
| restore 或 health-check 单独调用 | 报告完整，项目文件不被改写 |
| 已知失败但交接完整；或关键事实未检查 | 分别区分软件质量与上下文质量；未核验不能报 Good |
| 压缩中目标文档出现并行修改 | 重读合并，不覆盖并行内容 |

## 无旧聊天恢复验收

先对样例执行 compress，再让没有旧聊天的独立执行会话仅凭 Skill、项目文件和 Handoff 执行 restore。不给出预期结论；通过原始文件和执行产物评估它是否：

- 正确识别目标、实际架构、阶段、近期成果和当前任务。
- 保留关键约束与有效决策，区分实现偏差和新的合法决策。
- 核验当前基线，暴露必要证据缺口，而非只复述 Handoff。
- 给出能定位文件、具有验收方式的下一步。

只有任务授权和可用环境允许时执行该验收；不必为静态检查启动独立会话或代理。未执行的行为测试必须标为“未执行”，不能用格式检查代替。针对观察到的问题做窄修正，避免不断添加推测性规则。
