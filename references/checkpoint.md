# Checkpoint

先读取并应用 [共享状态重建规则](state-reconstruction.md)。保存开发过程的 WIP 断点，不是完成报告或正式账号交接。

1. 确认范围，定位并读取已有 checkpoint/current-work 文档、当前任务相关代码和差异。
2. 核验当前目标、任务、相对上次断点的进展、正在修改的文件/符号、阻碍和下一步。没有旧断点则明确首次记录，不能补造进展历史。
3. 按共享规则记录实现分类、Git 基线和验证；明确表达部分实现、正在修改、测试失败或尚未验证。禁止为了漂亮快照将半成品写成 completed。
4. 优先更新现有入口；没有合适入口时，按项目语言和布局使用 [Checkpoint 模板](../assets/checkpoint-template.md)，不强制 `.project-context` 目录。适用共享规则的写入冲突和有限同步边界。
5. 输出断点路径、WIP 摘要、验证状态、证据缺口和 Next Exact Action。

只保存可交接的事实、决策、结果、问题与下一步，不保存模型私有推理或 chain-of-thought。内容可以覆盖当前断点，但移走有价值的未提交历史前须确认另有已保存入口；不累积聊天流水账。一次检查时间更新不等于开发进展。此模式不创建正式 Handoff。
