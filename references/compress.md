# Compress / Handoff

先读取并应用 [共享状态重建规则](state-reconstruction.md)。下文只规定压缩流程与写入策略，不另定义事实优先级或验证分类。

## 工作流程

1. 按共享规则确认范围和文档映射；读取相关项目概述、架构、进度、决策、待办、问题及已有 Handoff。
2. 重建当前任务状态：定向检查代码、Git 与必要验证，归纳目标、技术栈、实际架构、当前阶段、近期成果、正在进行的任务、待办、决策、约束和问题。
3. **默认重点维护已有 Handoff。** 没有交接入口时，沿用项目文档位置与语言，使用 [Handoff 模板](../assets/handoff-template.md) 创建一份；无需为了匹配模板拆分已有文档或创建完整文档套装。
4. 按下面的有限同步规则处理其他文档。需要新增有依据的决策记录且无既有格式时，才参考 [决策模板](../assets/decision-template.md)。
5. 写入前重新检查目标内容是否被其他工作修改；变化后重读并合并。检查文档差异、引用和证据基线，避免覆盖用户未提交内容。
6. 输出交接文件入口、实际更新的文档、关键冲突/验证限制、待同步项及一个具体下一步。只建议新会话，不自动创建。

## 有限同步

仅当修改有明确证据、范围小、属于本次上下文同步且不改变既有决策或要求时，更新 Progress、TODO、Issues、Architecture 等文档。例如，按充分验收证据勾选当前任务，或修正已核实的入口路径。

遇到需要广泛重写、验收不明、存在并行改动或需作出产品/架构判断的内容，保留原文并报告“路径、过期主张、证据、建议同步动作”。影响下一步的待同步项同时在 Handoff 的问题或证据缺口中简记。

不要为一次简短压缩批量改写无关文档、改名整个文档体系或重新整理所有历史。保留有效历史；旧决策变更遵循共享冲突规则。

## 最小充分上下文

Handoff 是可更新的当前快照，不按会话追加流水账。保留足够信息让新会话先理解，再定位证据和继续工作；不能只剩一串链接。

- 包含模板所列的语义内容；已有格式可以合并标题，但 Evidence Scope / Verification Baseline 的字段不得遗漏。未知/不适用明确填写。
- 100–180 行仅为软参考，不是验收上限。优先保护当前任务、下一步、关键约束、未决风险、决策理由和必要证据。
- 最近成果压缩为能力/阶段摘要；完整历史沿用进度或已有归档，不复制全部提交列表和聊天探索过程。
- 当前优先待办保留在快照，完整 backlog 用路径引用；关键限制和影响当前动作的风险保留必要摘要。
- 决策摘要保存结论、理由、影响和原记录位置。Do Not Reconsider Unless Necessary 只列有依据的有效决定及重审条件；不要把猜测变成永久禁令。
- 测试输出保存命令、状态和关键失败摘要，不复制大段日志。证据位置用相对路径/符号，避免重复粘贴源码。
- 一个事实选一个主要维护位置，其余位置用简短摘要或链接。无变化不堆叠重复条目，仅核验时间更新不计作开发进展。
- 移走细节前确认其在原文档或已实际保存的历史中可找回；不能假设旧的未提交 Handoff 已被 Git 留存。

Next Recommended Action 优先给出一个能执行的任务，包含目标文件/模块、动作、验收方式与必要前置条件。状态不确定时先给最小核实任务，避免建议直接重做已存在功能。
